# Power BI 그래프 재현 가이드 (`aging_infra_flat.csv` 기준)

`figures/01~11_*.png`(Python으로 그린 그래프)와 최대한 똑같이 나오도록, Power BI Desktop에서
`aging_infra_flat.csv` 한 장만 가지고 클릭하는 순서를 적었다.

Power BI Desktop은 Windows 전용이다. Mac에서는 실행이 안 되므로(그래서 이 프로젝트도
Python 시각화로 대체했다), Windows PC나 Power BI 웹(app.powerbi.com)에서 진행한다.

---

## 0. 시작하기 전에 (한 번만 하면 되는 준비 작업)

### 0-1. 파일 불러오기

1. Power BI Desktop 실행 → **홈** 리본 → **데이터 가져오기** → **텍스트/CSV** 클릭
2. `aging_infra_flat.csv` 선택 → 열기
3. 미리보기 창 아래 **파일 원본**이 `65001: 유니코드(UTF-8)`로 되어 있는지 확인 (한글이 깨지면 이 드롭다운에서 UTF-8로 바꾸기)
4. **로드** 클릭 (변환이 더 필요하니 **데이터 변환**을 눌러도 됨 — 0-3에서 어차피 Power Query 편집기를 또 열 것임)

### 0-2. 컬럼과 데이터 타입 확인

불러온 뒤 화면 오른쪽 **필드** 창에 `aging_infra_flat` 테이블이 보여야 합니다. 컬럼은 다음과 같습니다.

| 컬럼명 | 의미 | Power BI 데이터 타입 확인 |
|---|---|---|
| country | 국가 (KR/JP) | 텍스트 |
| region_name_kr | 지역명(한글) | 텍스트 |
| region_name_local | 지역명(현지어, 일본만) | 텍스트 |
| year | 연도 | **정수(전체 숫자)** — 콤마(1,234) 서식이 잡혀 있으면 안 됨 |
| total_pop / elderly_pop / medical_beds / care_facility_count | 원본 절대값 | 소수 |
| aging_rate / pop_change_rate / medical_beds_per_10k / care_facility_per_10k | 계산된 비율·밀도 지표 | 소수 |

`year`를 클릭한 뒤 리본 상단 **열 도구** 탭 → **데이터 형식**이 "정수"인지, **서식**이 콤마 없는 일반 숫자인지 확인하세요.
(연도에 1,234 같은 천단위 콤마가 붙으면 차트 축이 이상하게 보입니다.)

### 0-3. 국가명을 한글로 보여줄 열 추가 (Power Query)

원본 그래프는 범례에 "KR/JP"가 아니라 "한국/일본"으로 표시됩니다. 똑같이 만들려면:

1. **홈** → **데이터 변환** (Power Query 편집기 열림)
2. **열 추가** 탭 → **조건 열** 클릭
3. 새 열 이름: `국가명`
4. 조건: `country` **같음** `KR` → 출력 `한국`, 그렇지 않으면 `일본`
5. 확인 → **닫기 및 적용**

이제 필드 창에 `국가명` 열이 생겼습니다. 아래 모든 차트의 **범례(Legend)** 자리에는 `country` 대신 이 `국가명`을 씁니다.

### 0-4. 국가별 색상 고정 (한국=파랑, 일본=주황)

figures 폴더의 그래프들과 색을 맞추려면 매번 차트를 만들 때마다:

1. 시각화 만든 뒤 오른쪽 **서식(페인트 롤러 아이콘)** 클릭
2. **시각적 개체** 탭 → **셀 요소** (또는 **색** / **데이터 색**) 펼치기
3. 계열 목록에서 **한국** 선택 → 색상 사각형 클릭 → **다른 색** → 16진수 입력란에 `#2A78D6`
4. **일본** 선택 → 16진수 `#EB6834`

| 국가 | 색 코드 |
|---|---|
| 한국 (KR) | `#2A78D6` (파랑) |
| 일본 (JP) | `#EB6834` (주황) |

## 1. Page 1. Overview — 전체 현황 (fig 01~04)

적재 데이터가 2015~2023으로 통일돼 있어(팀/보고서 요청, 2026-08-26) 인구·인프라 지표 모두 2023년이 최신 연도다. 원래는 인구 2024년/인프라 2023년으로 기준이 달랐으나, 일본 인프라 원본이 2023년까지만 공표돼 있어 인구도 2023년까지로 맞췄다.

### 1-1. KPI 카드 4개 (`01_overview_kpi.png`)

카드를 4개 반복해서 만듭니다.

| 카드 | 값 필드 | 필터 |
|---|---|---|
| 평균 고령화율 | `aging_rate` 를 드래그 → 필드 이름 옆 ▼ → **요약 안 함** 대신 **평균** 선택 | `year` = 2023 |

**만드는 법(카드 1개 기준):**

4. 시각화 창 아래 **필터** 영역에 `year` 드래그 → 필터 형식 "기본 필터링" → 2023만 체크
5. 서식에서 카드 제목을 "평균 고령화율(2023)"로 수정
6. 나머지 3개도 같은 방식으로 반복 (필드만 표 대로 바꿔서)

## 2. Page 2. Deep Dive — 상세 분석 (fig 05~07)

### 2-1. 산점도 2개 (`05_scatter_aging_vs_infra.png`)

1. **분산형 차트** 클릭
2. X축: `aging_rate`
3. Y축: `medical_beds_per_10k`
4. 범례: `국가명`
5. 필터: `year` = 2023
6. 서식 → **분석** 탭(돋보기 모양) → **추세선** 켜기 → 국가별 범례를 넣었으므로 한국/일본 각각 추세선이 자동으로 그려짐

같은 방식으로 Y축만 `care_facility_per_10k`로 바꿔서 두 번째 산점도 생성.

Power BI 추세선은 R²(결정계수)까지는 툴팁에 보여주지만 원본 그림처럼 상관계수 r 값을 텍스트로 정확히 표시하진 않는다. r 값(한국 +0.74, 일본 +0.82, 전체 -0.67)이 필요하면 4-1의 DAX 측정값을 참고.

### 2-2. 고령화율 상위/하위 10개 지역 (`06_region_ranking_aging.png`)

1. **가로 막대형 차트** 클릭
2. Y축: `region_name_kr`
3. 값: `aging_rate`
4. 범례: `국가명` (막대 색이 국가별로 구분되게)
5. 필터: `year` = 2023
6. 시각화 창 **필터** 영역에서 `aging_rate` 필터를 하나 더 추가 → 필터 형식을 **상위 N**으로 변경 → 10 입력, 값 기준 `aging_rate`
7. 정렬: 시각화 오른쪽 위 **...** → **축 정렬** → `aging_rate` 내림차순

하위 10개는 같은 차트를 복사해서 6번 필터를 **하위 N**(Bottom N)으로 바꾸면 됩니다.

### 2-3. 국가별 의료 vs 돌봄 구성비 (`07_medical_vs_care_composition.png`)

이 차트는 `medical_beds_per_10k`와 `care_facility_per_10k`를 "지표명 / 값" 두 열로 바꿔야(피벗 해제) 100% 누적 막대의 범례로 쓸 수 있습니다.

**Power Query에서 열 피벗 해제:**
1. **홈** → **데이터 변환**
2. `medical_beds_per_10k`, `care_facility_per_10k` 두 열을 Ctrl+클릭으로 같이 선택
3. 마우스 우클릭 → **다른 열 피벗 해제** 아님, **선택한 열만 피벗 해제** 클릭
4. 새로 생긴 두 열 이름을 각각 `지표`, `값`으로 변경 (열 헤더 더블클릭)
5. `지표` 열의 값이 `medical_beds_per_10k`/`care_facility_per_10k`로 되어 있는데, 원하면 조건 열로 "병상수"/"요양기관수" 한글 라벨을 추가로 만들어도 됨
6. **닫기 및 적용**

**차트 만들기:**
1. **100% 누적 가로 막대형 차트** 클릭
2. Y축: `국가명`
3. 범례: `지표`
4. 값: `값` → **합계**(원본 그림도 지역들을 다 더한 합계 기준으로 그렸습니다. 평균이 아님에 주의)
5. 필터: `year` = 2023

## 3. Page 3. Insight — 인프라 격차지수 (fig 08)

이 그래프는 "국가 내에서 고령화율 순위와 인프라밀도 순위 차이"를 계산해야 해서 DAX 계산 열이 필요합니다.
(기획서 3.4의 인프라 격차지수 DAX와 같은 방식이며, 다만 **국가별로 나눠서** 순위를 매깁니다 — 전체를 한 줄로 세우면 일본이 원래 고령화율 자체가 높아서 TOP15가 전부 일본으로 쏠리는 착시가 생기기 때문입니다.)

### 3-1. DAX 계산 열 3개 추가

**필드** 창에서 `aging_infra_flat` 테이블 우클릭 → **새 열**, 아래 3개를 순서대로 추가합니다.

```DAX
인프라밀도 = aging_infra_flat[medical_beds_per_10k] + aging_infra_flat[care_facility_per_10k]
```

```DAX
고령화율순위_국가내 =
RANKX(
    FILTER(
        aging_infra_flat,
        aging_infra_flat[country] = EARLIER(aging_infra_flat[country]) &&
        aging_infra_flat[year] = EARLIER(aging_infra_flat[year])
    ),
    aging_infra_flat[aging_rate], , DESC
)
```

```DAX
인프라순위_국가내 =
RANKX(
    FILTER(
        aging_infra_flat,
        aging_infra_flat[country] = EARLIER(aging_infra_flat[country]) &&
        aging_infra_flat[year] = EARLIER(aging_infra_flat[year])
    ),
    aging_infra_flat[인프라밀도], , DESC
)
```

```DAX
인프라격차지수 = aging_infra_flat[고령화율순위_국가내] - aging_infra_flat[인프라순위_국가내]
```

값이 **더 음수일수록** "고령화율은 상위권인데 인프라는 하위권" = 그 나라 안에서 인프라 확충이 시급한 지역입니다.

### 3-2. 차트 만들기

원본처럼 국가별 TOP10씩 한 화면에 놓으려면 차트 2개(한국용/일본용)를 나란히 두는 게 가장 쉽습니다.

1. **가로 막대형 차트** 클릭
2. Y축: `region_name_kr`
3. 값: `인프라격차지수`
4. 범례: `국가명` (색 구분용)
5. 필터: `year` = 2023, **그리고** `country` = KR
6. `인프라격차지수` 필터 추가 → 필터 형식 **하위 N** → 10 (가장 음수인, 즉 가장 시급한 지역이 위로 오도록)
7. 축 정렬: `인프라격차지수` 오름차순

같은 차트를 복사해서 5번 필터만 `country = JP`로 바꾸면 일본용 TOP10이 나옵니다.

## 4. (심화/선택) 발표 보조 그래프 — fig 09~11

시간이 되면 만들면 좋지만, 필수는 아닙니다. 핵심 수치는 이미 `docs/기획서.md` 3.4 Insight에 텍스트로 정리돼 있으니, 텍스트 상자로 옮겨 적기만 해도 발표에는 충분합니다.

### 4-1. Simpson's Paradox 산점도 (`09_simpsons_paradox_care.png`)

2-1에서 만든 "고령화율 × 요양기관수" 산점도에 범례(`국가명`)가 이미 들어가 있으면 **분석 → 추세선**을 켜는 순간 한국/일본 각각의 추세선이 자동으로 그려집니다. 전체 통합 추세선까지 보이게 하려면 같은 산점도를 하나 더 복사해서 범례를 빼면(전체를 한 덩어리로) 됩니다. 상관계수 숫자(한국 +0.74 / 일본 +0.82 / 전체 -0.67)는 텍스트 상자로 따로 적어 넣으세요.

### 4-2. 2015→2023 고령화율 증가폭 TOP15 (`10_aging_increase_top_regions.png`)

계산 열이 하나 더 필요합니다 (지역별로 2023년 값 - 2015년 값):

```DAX
증가폭_2015_2023 =
VAR y2023 =
    CALCULATE(
        SUM(aging_infra_flat[aging_rate]),
        aging_infra_flat[year] = 2023,
        ALLEXCEPT(aging_infra_flat, aging_infra_flat[region_name_kr], aging_infra_flat[country])
    )
VAR y2015 =
    CALCULATE(
        SUM(aging_infra_flat[aging_rate]),
        aging_infra_flat[year] = 2015,
        ALLEXCEPT(aging_infra_flat, aging_infra_flat[region_name_kr], aging_infra_flat[country])
    )
RETURN y2023 - y2015
```

가로 막대형 차트: Y축 `region_name_kr`, 값 `증가폭_2015_2023`(평균으로 집계 — 지역당 값이 하나뿐이라 평균을 해도 그 값 그대로 나옴), 상위 N 필터 15.

### 4-3. 전역 랭킹 vs 국가별 랭킹 대조 (`11_global_vs_country_ranking.png`)

3-1의 `고령화율순위_국가내`/`인프라순위_국가내`처럼 **국가 조건 없이** 전체를 한 줄로 세우는 버전을 계산 열로 하나 더 만들면(FILTER 조건에서 `country = EARLIER(country)` 부분만 빼면 됨) 왼쪽 차트(전역 랭킹)를 만들 수 있습니다. 오른쪽은 3-2에서 만든 국가별 TOP10 차트를 그대로 재사용하면 됩니다.

## 6. 있어보이는 ERD 만들기 (스노우플레이크 모델, 4테이블)

지금까지는 `aging_infra_flat.csv` 한 장으로 차트만 빨리 뽑는 방법이었습니다. 팀/선생님께 **관계도(ERD)** 를 보여줘야 한다면, `data/powerbi_export/` 폴더의 4개 파일로 국가 차원을 분리하고 팩트 테이블을 인구/인프라로 나눈 정규화된 모델을 만들 수 있습니다.

### 왜 이렇게 나눴나

- 국가(Dim_Country) 분리: 기존에는 `country`(KR/JP) 값이 지역 테이블에 코드값으로만 반복 저장돼 있었다. 국가를 별도 차원으로 빼서 국가명·데이터출처·소속 지역 수 같은 속성을 붙일 수 있게 정규화했다.
- 팩트를 인구(Fact_Population)/인프라(Fact_Infra)로 분리: 원래 인구 지표(총인구·고령화율 등)는 2015~2024년까지 있었지만 인프라 지표(병상수·요양기관수)는 일본 원자료가 2023년까지만 있었다. 지금은 적재 연도 자체를 2015~2023으로 통일해서(팀/보고서 요청) 두 팩트 모두 결측이 없지만, 인구와 인프라를 개념적으로 나눠서 관리한다는 구조는 그대로 유지했다.
- 날짜(Dim_Date)는 별도 테이블로 안 둠: 연도(`year`) 숫자 하나만 있고 분기·월 같은 부가 정보가 없는 차원이라, 굳이 테이블을 하나 더 두지 않고 `Fact_Population`/`Fact_Infra`에 `year`를 바로 넣었다. 부가 속성이 없는 얇은 차원까지 테이블로 쪼개는 것보다, 꼭 필요한 관계만 남기는 게 더 정직한 설계다.

### 6-1. 파일 불러오기

`data/powerbi_export/` 폴더에 CSV 6개가 있는데, 이 중 **4개만** 씁니다.

| 파일 | 용도 |
|---|---|
| `Dim_Country.csv` | 사용 |
| `Dim_Region.csv` | 사용 |
| `Fact_Population.csv` | 사용 (컬럼에 `date_id` 대신 `year`가 바로 들어있음) |
| `Fact_Infra.csv` | 사용 (컬럼에 `date_id` 대신 `year`가 바로 들어있음) |
| `Dim_Date.csv` | 쓰지 않기 — 이 4테이블 모델에서는 `year`가 Fact 테이블에 이미 들어있어서 필요 없다. (3번 "기본 ERD" 버전을 만들 때만 사용) |
| `Fact_RegionStats.csv` | 쓰지 않기 — Fact_Population/Fact_Infra와 같은 데이터를 담고 있어서, 같이 불러오면 관계가 중복돼 모델이 헷갈려진다. |

1. **홈** → **데이터 가져오기** → **텍스트/CSV**
2. 위 표에서 "사용"인 4개 파일을 하나씩 반복해서 불러옵니다 (한 번에 하나씩, 파일 원본 인코딩 UTF-8 확인)

### 6-2. 관계 잇기 (모델 보기)

1. 왼쪽 세로 탭에서 **모델 보기** 클릭 (테이블 아이콘 여러 개가 박스로 보이는 화면)
2. 아래 3개 관계를 마우스로 직접 드래그해서 연결합니다 (필드를 다른 테이블의 같은 이름 필드 위로 끌어다 놓으면 자동으로 관계가 생김):

| 시작 (1쪽) | 끝 (N쪽) |
|---|---|
| `Dim_Country[country]` | `Dim_Region[country]` |
| `Dim_Region[region_id]` | `Fact_Population[region_id]` |
| `Dim_Region[region_id]` | `Fact_Infra[region_id]` |

3. 관계선 3개가 생기면 `Dim_Country → Dim_Region → (Fact_Population / Fact_Infra)` 모양의 스노우플레이크 구조가 화면에 보입니다 — 이게 ERD입니다.

### 6-3. 참고: 이제 차트는 어떻게 만드나요?

5장까지 만든 차트들은 전부 `Fact_Population`이나 `Fact_Infra`의 필드를 그대로 쓰면 됩니다(컬럼 이름이 동일하고, 연도 필터도 `year` 컬럼을 그대로 씀). 다만 국가 이름을 표시할 땐 `Dim_Region[country]`(KR/JP) 대신 `Dim_Country[country_name_kr]`(한국/일본)을 범례로 쓰면 관계를 타고 자동으로 연결됩니다.
