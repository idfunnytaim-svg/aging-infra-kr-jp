## 2. 발견된 문제 (우선순위순)

### 2.1 일본 인구 데이터가 5년 단위(census)라 매년 고령화율을 못 만드는 문제

원래 `estat_A_인구세대_prefecture.csv`는 국세조사(census, 0000020201) 원자료라 2015년·2020년 딱 2개년만 존재했다.

e-Stat의 인구추계(人口推計) 統計表010으로 소스를 교체해 해결했다(`scripts/collect_estat_japan.py`, 2026-08-24 수정). 인구추계는 census를 벤치마크로 출생·사망·이동 통계를 결합해 총무성 통계국이 매년 10월 1일 기준으로 공식 발표하는 추계치이고, 도도부현 단위로 이미 제공된다.

- 平成27年(2015)국세조사 기준 시리즈(statsDataId=0003459027): 2015~2019
- 令和2年(2020)국세조사 기준 시리즈(statsDataId=0003448237): 2020~2024
- 두 시리즈를 이어붙여 빈틈·중복 없이 2015~2024 매년, 47도도부현, 총인구·65세이상인구를 확보했다(65세이상은 5세계급 65~69/70~74/75~79/80~84/85세이상 5개 구간 합산).
- 단위 주의: 이 통계표 원 단위는 千人(천명)이다. 실인원수(다른 e-Stat 표·KOSIS와 단위 통일)로 맞추려고 스크립트에서 ×1000 처리했다.

결과적으로 한국·일본 모두 2015~2024 매년 데이터로 대칭적으로 분석 가능해졌다. 기존에 논의하던 (a)비대칭 허용 / (b)2015·2020만 비교 방안은 더 이상 필요 없다. 코로나(2020~2022) 기간도 별도 변수로 구분하지 않고 2015~2024 전체를 하나의 시계열로 다루기로 했다(2026-08-24 결정).

### 2.2 한국 KOSIS 3개 파일에 시도·시군구가 섞여 있다

`kosis_고령인구비율.csv`, `kosis_주민등록인구현황.csv`, `kosis_의료기관병상수.csv`는 region 컬럼에 전국 + 17개 시도 + 229개 시군구(+읍면동/출장소까지)가 다 섞여서 들어있다. 프로젝트는 시도 단위 분석인데 그대로 SQL에 넣으면 서울특별시 값과 강남구 값이 같은 레벨로 뒤섞여 집계가 틀어진다.

경기도 안에도 `광주시`가 있고 별도로 `광주광역시`도 있어서, 이름만 보고 필터링하면 잘못 걸러질 수 있다. 전처리 때 정확히 아래 17개 시도명 리스트와 일치하는 행만 남겨야 한다.

```
서울특별시, 부산광역시, 대구광역시, 인천광역시, 광주광역시, 대전광역시, 울산광역시,
세종특별자치시, 경기도, 강원특별자치도, 충청북도, 충청남도, 전북특별자치도,
전라남도, 경상북도, 경상남도, 제주특별자치도
```

`kosis_장기요양기관현황.csv`는 이미 17개 시도 + `합계`만 있어서 이 문제가 없다(`합계` 행은 전국 총계라 시도별 분석에서는 제외해야 한다).

### 2.3 `kosis_주민등록인구현황.csv`는 사실상 중복 데이터

지난 세션에서 "이 파일이 왜 있는지 확인 필요"로 남겨뒀던 항목이다. 확인해보니 `kosis_고령인구비율.csv`에 이미 `전체인구(B)` 항목으로 같은 총인구 수치가 들어있다(기획서 2.1의 "별도 수집 불필요" 설명과 일치). 이 파일은 전처리 단계에서 사용하지 않고 `data/raw/`에 원본 기록용으로만 남겨둔다(지우지는 않는다 — 나중에 남녀 인구비 등 추가 분석에 쓸 수도 있다).

### 2.4 지역명 매핑 테이블이 아직 없다

기획서 2.3에 "한국 시도명 ↔ 일본 도도부현명 매핑 테이블 구축" 계획은 있지만 실제 매핑 파일/코드는 아직 작성하지 않았다. 한국 17개 시도와 일본 47개 도도부현은 개수가 다르므로 1:1 매핑이 아니라, 각자 `Dim_Region`에 `country`(KR/JP) 구분자를 넣어 나란히 저장하는 방식(기획서 2.4 스키마)으로 가면 된다. 매핑이라기보다는 국가 코드 부여 + 지역명 정리에 가깝다.

### 2.5-1 한국 의료기관 병상수 데이터가 아예 수집되어 있지 않았다

기획서 2.1에는 "의료기관 병상수(한국, 시도) — KOSIS e-지방지표 themaId=A_01_03"이 수집 대상으로 명시돼 있었는데, 실제 `collect_kosis_korea.py`의 `KOSIS_TABLES`에는 고령인구비율·장기요양기관현황만 있었고 병상수 항목이 빠져 있었다. 방치했다면 3.1 Q3("고령화율과 의료 인프라(병상수) 관계")를 한국 쪽에서 답할 수 없었다.

e-지방지표(kosis.kr/visual/eRegionJipyo)는 시각화 전용 서비스라 표준 Open API(`statisticsParameterData`)와 별개인데, 같은 수치를 담은 정식 통계표를 찾았다: `DT_1YL20971`(인구 천명당 의료기관병상수, 시도/시/군/구, orgId=101). 총병상수(A)·주민등록인구(B)·인구천명당병상수(A÷B×1000) 3개 항목, 2015~2024 매년, 17개 시도 포함을 확인했다.

`collect_kosis_korea.py`의 `KOSIS_TABLES`에 `"의료기관병상수": ("101", "DT_1YL20971", 1)`을 추가하고 재수집해 `data/raw/kosis_의료기관병상수.csv`를 생성했다(2026-08-24).

### 2.5 컬럼명 통일 (미완료)

일본 원본은 항목명이 일본어(`A1101_総人口`, `I5211_病院病床数` 등)로 되어 있어 한글/영문 표준 컬럼명(`total_population`, `hospital_beds` 등)으로 매핑해야 한다(기획서 2.3에 계획됨, 아직 코드는 없음). 한국/일본 모두 long format(지역-항목-연도-값)이라 구조 자체는 같아서 합치기는 어렵지 않다.

## 3. 전처리 스크립트에서 처리해야 할 순서 (제안)

1. 한국 KOSIS 2개 파일에서 위 17개 시도명 리스트로 필터링 (`kosis_고령인구비율.csv`, `kosis_주민등록인구현황.csv`는 참고용으로 skip)
2. `kosis_장기요양기관현황.csv`에서 `합계` 행 제외
3. 일본 3개 파일의 일본어 항목명을 표준 컬럼명으로 매핑
4. 연도 범위는 2015~2024 공통 구간으로 통일 (일본 의료·복지는 2015~2023까지만 있으므로 해당 항목만 2023까지, 인구·한국 데이터는 2024까지)
5. 파생변수 계산: 고령화율(일본), 인구 1만명당 병상수, 인구 1만명당 요양기관수, 인프라 격차지수 (기획서 1.6)
6. `Dim_Region`(country/region_name_kr/region_name_local), `Dim_Date`, `Fact_RegionStats` 스키마로 합쳐서 DB 적재
