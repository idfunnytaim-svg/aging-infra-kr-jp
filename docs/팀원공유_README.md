# 데이터 파일 안내 (팀원 공유용, 2026-08-31 갱신)

한·일 지역별 고령화·의료돌봄 인프라 데이터입니다. 목적에 맞는 폴더/파일을 골라 쓰세요.

2026-08-26(v4)에 바뀐 점: 적재 데이터를 2015~2023(9개년)으로 통일했다. 원래 인구 지표는 2024년까지 있었는데 일본 인프라(병상수·요양기관수) 원자료가 2023년까지만 공표돼 있어서, 전체를 2023년까지로 잘라 모든 파일에 빈 값이 하나도 없도록 만들었다(보고서에도 그대로 쓸 수 있게, 팀 요청 반영). 행 수가 전체적으로 줄었다(예: 640행 → 576행). `figures/`도 이 기준으로 재생성했다.

2026-08-31에 바뀐 점: `powerbi_export/`의 출처가 pandas 파이프라인에서 SQL 정제 파이프라인(`sql_cleaning/`) 기준으로 교체됐다. 값은 기존과 동일하고, 4번(기본 ERD)·5번(스노우플레이크) 두 옵션 다 그대로 제공한다.

---

## 어떤 걸 써야 하나요?

| 하고 싶은 것 | 쓸 파일 |
|---|---|
| Power BI에 그냥 빨리 넣어서 차트만 보고 싶다 | `aging_infra_flat.csv` 한 장만 |
| Power BI에서 **차트/ERD를 실제로 어떻게 클릭해서 만드는지** 순서가 필요하다 | `PowerBI_가이드.md` |
| **각 컬럼(변수)이 무슨 뜻인지** 모르겠다 | `데이터사전.md` |
| Power BI에서 **기본 ERD(3테이블)** 를 보여줘야 한다 | `powerbi_export/Dim_Region.csv` + `Dim_Date.csv` + `Fact_RegionStats.csv` |
| Power BI에서 **더 있어보이는 ERD(스노우플레이크, 4테이블)** 를 보여주고 싶다 | `powerbi_export/Dim_Country.csv` + `Dim_Region.csv` + `Fact_Population.csv` + `Fact_Infra.csv` |
| 원본 데이터가 어떻게 정제됐는지 확인하고 싶다 | `cleaned/` 폴더 7개 파일 + `전처리_로그.md` |

## 1. `aging_infra_flat.csv` — 가장 간단한 버전

지역(한국 17개 시·도 + 일본 47개 도도부현) × 연도(2015~2023) 조합마다 한 행, 총 576행짜리 표 하나입니다. 빈 값이 없습니다(`pop_change_rate`의 각 지역 2015년 행 제외).

**Power BI 사용법**: 홈 → 데이터 가져오기 → 텍스트/CSV → 이 파일 선택. 끝. 관계 설정 필요 없이 바로 차트/필터 만들 수 있습니다. 실제로 어떤 시각화를 어떻게 만드는지는 `PowerBI_가이드.md` 1~5장을 그대로 따라 하면 됩니다. 컬럼별 뜻은 `데이터사전.md`에 전부 정리돼 있습니다.

---

## 2. `PowerBI_가이드.md` — 그래프·ERD를 실제로 만드는 클릭 순서

`figures/01~11_*.png`(팀이 만든 그래프)를 Power BI에서 그대로 재현하는 방법과, 4번의 ERD를 실제로 어떻게 만드는지를 시각화 종류·필드 위치·필터값까지 순서대로 적어놓았습니다. Power BI를 처음 써보는 팀원은 이 파일부터 읽는 걸 추천합니다.

- 0장: 파일 불러오기, 국가명 한글 라벨 만들기, 색상 고정
- 1~3장: 그래프 11장 재현 (fig01~11)
- 4장: 발표 보조 그래프(선택)
- **6장: 있어보이는 ERD 만들기** — 아래 4번(`powerbi_export/` 4개 파일)로 스노우플레이크 관계도를 실제로 잇는 순서

---

## 3. `데이터사전.md` — 각 컬럼이 무슨 뜻인지

`aging_rate`, `medical_beds_per_10k` 같은 컬럼의 의미·단위·계산식·실제 예시(서울 2023년 고령화율 18.5% 등)를 정리했다. 국가 간 비교할 때 조심해야 할 정의 차이(병상수·요양기관수)와 값이 비어있는 경우도 따로 정리돼 있다.

---

## 4. `powerbi_export/` — 기본 ERD(테이블 관계도)용, 3개 파일

DB의 별(star) 스키마를 그대로 CSV 3장으로 쪼갠 것입니다. Power BI에서 관계를 직접 이어야 ERD가 보입니다.

2026-08-31부터 이 파일들의 출처가 바뀌었다. 기존에는 `preprocess_and_load.py`(pandas)가 만든 `aging_infra.db`에서 뽑았는데, 이제는 `sql_cleaning/00~17.sql`(SQL로 정제·병합·ERD 조립)이 만든 `data/cleaning_process.db`에서 `scripts/export_csv_for_powerbi_from_sql.py`로 뽑는다. 두 DB는 값이 소수점 6자리까지 100% 일치함이 검증됐으므로 숫자는 바뀌지 않는다. 같은 날 `Fact_RegionStats.csv`의 연도 컬럼도 `date`(실제 연도값)에서 `date_id`(1~9 순번, DB 물리 테이블과 동일)로 되돌렸다. 발표에서 `Dim_Date`와의 관계가 정식 FK(외래키)라는 걸 바로 보여주기 위해서다.

| 파일 | 역할 | 키 컬럼 |
|---|---|---|
| `Dim_Region.csv` (64행) | 지역 정보 | region_id (PK) |
| `Dim_Date.csv` (9행) | 연도 정보 | date_id (PK) |
| `Fact_RegionStats.csv` (576행) | 실제 수치 | region_id (FK), date_id (FK) |

**Power BI 사용법**:
1. 세 파일을 각각 "가져오기 → 텍스트/CSV"로 불러온다.
2. **모델 보기**로 이동.
3. `Dim_Region[region_id]`를 드래그해서 `Fact_RegionStats[region_id]`에 연결 (1:N).
4. `Dim_Date[date_id]`를 드래그해서 `Fact_RegionStats[date_id]`에 연결 (1:N).

## 5. `powerbi_export/` — 더 있어보이는 ERD(스노우플레이크, 4개 파일)

국가(country)를 별도 차원으로 분리하고, 인구 지표와 인프라 지표를 별도 팩트로 나눈 버전입니다. v1(5테이블)보다 부가 정보 없이 얇기만 한 `Dim_Date` 테이블을 없애 4테이블로 다듬었습니다(`year`를 Fact 테이블에 자연키로 직접 넣음). `Dim_Country.region_count`(소속 지역 수)는 팀원 리뷰를 반영해 다시 포함했습니다. 적재 연도를 2015~2023으로 통일한 뒤로는 두 Fact 테이블 모두 행 수가 같습니다(576행씩). (이 파일들도 4번과 마찬가지로 2026-08-31부터 SQL 정제 결과 기준입니다.)

| 파일 | 역할 | 키 컬럼 |
|---|---|---|
| `Dim_Country.csv` (2행) | 국가 정보(국가명·데이터출처·소속 지역 수) | country (PK) |
| `Dim_Region.csv` (64행) | 지역 정보 (country는 Dim_Country 참조) | region_id (PK), country (FK) |
| `Fact_Population.csv` (576행) | 인구 지표(총인구·고령화율 등, `year` 컬럼 직접 보유, 결측 없음) | region_id (FK) |
| `Fact_Infra.csv` (576행) | 인프라 지표(병상수·요양기관수, `year` 컬럼 직접 보유, 결측 없음) | region_id (FK) |

`Dim_Date.csv`, `Fact_RegionStats.csv`는 이 버전과 같이 쓰지 않는다. 4번(기본) 아니면 5번(스노우플레이크) 중 하나만 고른다.

**Power BI 사용법**: `PowerBI_가이드.md` 6장에 관계 3개를 잇는 순서까지 그대로 적혀 있습니다.

## 참고: 국가 간 비교 시 주의할 점

- `medical_beds`(병상수): 한국은 "총병상수" 1개 항목, 일본은 "병원 병상수 + 일반진료소 병상수"를 더한 값 — 집계 범위가 완전히 같지는 않습니다.
- `care_facility_count`(장기요양기관수): 한국은 방문요양·주야간보호·노인요양시설 등 **모든 서비스유형을 합친 수**, 일본은 그중 **입소시설(특별양호노인홈) 한 종류만** 센 수 — 정의 범위가 크게 달라서 절대값을 국가 간 직접 비교하면 안 됩니다(국가 내부 비교·추이만 유효). 자세한 내용은 `데이터사전.md` 참고.
