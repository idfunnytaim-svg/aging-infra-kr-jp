# 전처리 로그 — 원본 → 정제 → 최종 DB

`data/raw/`의 원본 CSV 7개가 `data/aging_infra.db`(`Fact_RegionStats`)까지 어떤 단계와 수식을 거쳐 만들어지는지 기록한다. Power BI에서 ERD를 볼 때 각 컬럼의 출처와 계산식을 확인하는 용도로 쓴다.

관련 산출물: `data/cleaned/`(원본 7개 파일을 1:1로 정제한 CSV, 1장과 동일한 규칙), `data/powerbi_export/`(최종 DB 3테이블 CSV), `data/aging_infra_flat.csv`(최종 DB를 region×year 단위 한 장으로 합친 CSV). 실행 스크립트는 `scripts/export_cleaned_sources.py`(1장), `scripts/preprocess_and_load.py`(1~3장), `scripts/export_csv_for_powerbi.py`/`export_for_powerbi.py`(4장).

---

## 1. 원본 CSV → 정제 CSV (`data/cleaned/`, 파일 1:1 대응)

원본 7개는 모두 long format(지역-항목-연도-값)이고, 나라마다 형식이 달라 각각 다르게 정제한다.
공통 지역 필터: 한국은 `KR_REGIONS_17`(정확히 일치하는 17개 시도명만), 일본은 47도도부현
한자→한글 매핑(`JP_PREF_KR`) — 둘 다 `scripts/preprocess_and_load.py`에 정의됨.

| # | 원본 파일 | 정제 결과 컬럼 | 처리 규칙 |
|---|---|---|---|
| 1 | `estat_A_인구세대_prefecture.csv` | region_name_kr, region_name_local, year, **total_pop**, **elderly_pop** | `cat01_name`을 `total_pop`(A1101_総人口)/`elderly_pop`(A1303_65歳以上人口)으로 피벗. 원자료 단위가 千人(천명)이라 수집 단계(`collect_estat_japan.py`)에서 이미 ×1000 해서 실인원수로 변환돼 있음. |
| 2 | `estat_I_의료_prefecture.csv` | region_name_kr, region_name_local, year, **medical_beds** | `I5211`(병원 병상수) + `I5212`(일반진료소 병상수) **합산**해서 `medical_beds`로 사용. 2024년분은 원자료 자체가 없어 결과에 없음(2015~2023, 9개년만). |
| 3 | `estat_J_복지_prefecture.csv` | region_name_kr, region_name_local, year, **care_facility_count** | `介護老人福祉施設数`(시설수)만 사용, `介護老人福祉施設定員数`(정원수)는 버림. 2024년분 없음(2015~2023). |
| 4 | `kosis_고령인구비율.csv` | region_name_kr, year, **total_pop**, **elderly_pop**, aging_rate_source | 원본에 전국+17개 시도+229개 시군구가 섞여 있어 17개 시도명과 **정확히 일치**하는 행만 필터링. `item`을 `total_pop`(전체인구(B))/`elderly_pop`(65세이상인구(A))으로 피벗. `aging_rate_source`는 KOSIS가 이미 계산해 둔 고령인구비율(A÷B×100) 원본값 — 최종 DB의 `aging_rate`는 이 값을 그대로 쓰지 않고 `elderly_pop`/`total_pop`으로 **직접 재계산**함(두 값은 반올림 오차 이내로 거의 같음). |
| 5 | `kosis_의료기관병상수.csv` | region_name_kr, year, **medical_beds** | 17개 시도 필터링 후 `item == "총병상수(A)"` 행만 사용. `주민등록인구(B)`·`인구천명당병상수` 항목은 버림(최종 DB에서 직접 재계산하므로). |
| 6 | `kosis_장기요양기관현황.csv` | region_name_kr, year, **care_facility_count** | `region != "합계"`(전국 총계 제외) AND `item == "기관수"` AND **`category2 == "계"`**(방문요양·주야간보호 등 세부유형 행 제외 — 안 걸러내면 같은 region+year에 중복 행이 생김). `정원` 항목은 버림. |
| 7 | `kosis_주민등록인구현황.csv` | region_name_kr, year, **total_pop** | 최종 DB에는 미사용(4번 파일의 total_pop과 값이 동일한 중복 데이터, `docs/원본데이터_점검.md` 2.3 참고). 참고용으로 동일 규칙(17개 시도, `item == "총인구수"`)으로만 정제해 보존. |

## 2. 정제 CSV → 병합(국가별 하나의 표로)

`scripts/preprocess_and_load.py`의 `load_korea()`/`load_japan()`이 위 표의 파일들을
`region + year` 키로 병합한다 (merge 순서: 인구 파일을 기준으로 병상수·요양기관수를 left join).

- 한국: 4번(인구) ⟵ 5번(병상수) ⟵ 6번(요양기관수), 7번은 병합에 사용 안 함
- 일본: 1번(인구) ⟵ 2번(병상수) ⟵ 3번(요양기관수)
- 두 나라 결과를 `pd.concat`으로 세로로 합친 뒤 `country` 컬럼(KR/JP)으로 구분

## 3. 파생 컬럼 수식 (전부)

`Fact_RegionStats`의 각 컬럼이 어떻게 계산되는지 — 컬럼 정의는 `sql/ddl/create_tables.sql`,
계산 코드는 `scripts/preprocess_and_load.py`의 `add_derived_columns()` 참고.

| 컬럼 | 수식 | 비고 |
|---|---|---|
| `total_pop` | (2장에서 병합된 원본값 그대로) | 총인구(명) |
| `elderly_pop` | (2장에서 병합된 원본값 그대로) | 65세이상인구(명) |
| `medical_beds` | (2장에서 병합된 원본값 그대로) | 의료기관 병상수(개) |
| `care_facility_count` | (2장에서 병합된 원본값 그대로) | 장기요양(개호) 기관수(개) |
| `aging_rate` | **`elderly_pop ÷ total_pop × 100`** | 고령화율(%). 한국 KOSIS 원본에도 동일 계산식의 값이 있으나(위 4번 파일 `aging_rate_source`), 한/일 계산 방식을 통일하기 위해 두 나라 모두 이 수식으로 직접 재계산함 |
| `pop_change_rate` | **`(total_pop − 전년도 total_pop) ÷ 전년도 total_pop × 100`** | 전년 대비 인구증감률(%). `country + region_name_kr` 그룹 내에서 연도순 정렬 후 1행씩 shift해서 계산. 각 지역의 첫 연도(2015)는 전년도가 없어 NULL |
| `medical_beds_per_10k` | **`medical_beds ÷ (total_pop ÷ 10,000)`** | 인구 1만명당 병상수. 일본 2024년은 `medical_beds`가 없어(1장 참고) 자동으로 NULL |
| `care_facility_per_10k` | **`care_facility_count ÷ (total_pop ÷ 10,000)`** | 인구 1만명당 요양기관수. 일본 2024년은 NULL |

### 국가 간 비교 시 주의할 정의 차이 (Insight 3, `docs/기획서.md` 참고)

- `medical_beds`: 한국은 "총병상수(A)"(병원+의원 구분 없이 통합) 1개 항목, 일본은 "병원 병상수 + 일반진료소 병상수" 2개 항목을 더한 값 — 집계 방식이 정확히 같지는 않음.
- `care_facility_count`: 한국은 방문요양·주야간보호·노인요양시설 등 **모든 장기요양 서비스유형을 합친 기관수**, 일본은 그중 **입소시설(특별양호노인홈) 한 유형만** 센 수 — 정의 범위가 크게 달라 절대값을 국가 간 직접 비교하면 안 됨(국가 내부 비교/추이만 유효).
