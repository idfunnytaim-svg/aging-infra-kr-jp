# 1. 프로젝트 개요 및 문제 정의
## Project Overview

### 1.1 프로젝트명

**프로젝트명:** 한·일 지역별 고령화와 의료·돌봄 인프라 격차 분석


### 1.2 프로젝트 주제

**분석 대상:** 한국 17개 시·도 / 일본 47개 도도부현

**해결하고자 하는 문제:** 한국과 일본은 모두 고령화가 많이 진행된 나라지만, 지역별로 고령화 속도와 인프라 대응 수준은 크게 다르다. 어느 지역이 고령화에 가장 취약한지, 고령화가 심한데도 의료·돌봄 인프라가 이를 따라가지 못하는 지역은 어디인지를 데이터로 파악한다.

**분석 기간:** 2015~2023 (양국 모두 결측 없이 확보 가능한 공통 연도로 통일)

**분석 지역/대상:** 한국 시·도 단위, 일본 도도부현 단위 (기초 행정단위는 국가 간 규모 차이가 커서 광역 단위로 통일)


### 1.3 기획 배경

- 현재 어떤 문제가 있는가? 한국과 일본 모두 고령화율이 지역별로 큰 편차를 보이며, 일부 지역은 고령인구 비율이 높음에도 의료·돌봄 인프라가 이를 따라가지 못하고 있다.
- 왜 이 문제가 중요한가? 인프라가 뒷받침되지 않는 고령화는 지역 의료 공백, 돌봄 부담 증가, 지역소멸 가속화로 이어질 수 있다.
- 데이터를 통해 무엇을 확인할 수 있는가? 지역별 고령화율과 의료·돌봄 인프라 밀도의 상관관계, 국가 간 인프라 대응 수준의 차이, 향후 인프라 확충이 시급한 지역을 정량적으로 확인할 수 있다.
- 분석 결과를 실제로 어디에 활용할 수 있는가? 지역별 인프라 투자 우선순위 설정, 정책 참고자료, 한일 고령화 대응 방식 비교연구 등에 활용할 수 있다.


### 1.4 프로젝트 목적

본 프로젝트를 통해 다음의 목적을 달성한다.

1. 한국과 일본의 지역별 고령화 추이를 동일 기준으로 비교·시각화한다.
2. 고령화율과 의료·돌봄 인프라 수준 간의 관계를 데이터로 검증한다.
3. 인프라 확충이 시급한 지역을 도출하여 실행 가능한 제안으로 연결한다.


### 1.5 분석 목표

최종 Power BI 대시보드를 통해 다음 질문에 답하는 것을 목표로 한다.

1. 한국과 일본의 지역별 고령화율은 최근 몇 년간 어떻게 변화했는가?
2. 고령화율이 높은 지역과 인구감소율이 높은 지역은 일치하는가?
3. 고령화율과 의료 인프라(병상수) 사이에는 어떤 관계가 있는가?
4. 고령화율과 돌봄 인프라(장기요양기관 수) 사이에는 어떤 관계가 있는가?
5. 고령화 대비 인프라가 가장 부족하여 향후 확충이 필요한 지역은 어디인가?


### 1.6 핵심 KPI

| KPI | 정의 | 산출 방법 |
|---|---|---|
| 고령화율 | 전체 인구 중 65세 이상 비율 | 65세이상인구 ÷ 총인구 × 100 |
| 인구증감률 | 전년 대비 인구 변화율 | (당해연도 인구 − 전년도 인구) ÷ 전년도 인구 |
| 인구 1만명당 의료기관 병상수 | 지역 의료 인프라 밀도 | 병상수 ÷ (총인구 / 10,000) |
| 인구 1만명당 장기요양기관 수 | 지역 돌봄 인프라 밀도 | 장기요양기관 수 ÷ (총인구 / 10,000) |
| 인프라 격차지수 | 고령화율 대비 인프라 수준의 상대적 부족 정도 | 고령화율 순위 − (의료+돌봄 인프라밀도) 순위 (자체 산출 파생지표) |

- 분석 가능한 변수: 고령화율, 인구증감률, 의료기관 병상수, 장기요양기관 수 등 연속형 수치 변수를 다수 확보할 수 있어 상관관계·추이 분석이 가능하다.

# 2.3 데이터 전처리 계획

아래 표는 `scripts/preprocess_and_load.py`의 실제 구현을 기준으로 정리했다.

| 전처리 항목 | 처리 방법 | 실제 구현 위치 |
|---|---|---|
| 결측치 | 일본 인프라 원자료가 2023년까지만 존재해, 보간 대신 **적재 연도 자체를 2015~2023으로 통일**해 결측이 애초에 생기지 않도록 사전 차단 | `preprocess_and_load.py`의 `YEARS`, `combined[combined["year"].isin(YEARS)]` |
| 중복 데이터 | "지역명+연도" 기준 사후 제거 대신, 원본 통계표의 세부 분류축(item/category)을 필요한 값 하나로 필터링해 중복 자체가 생기지 않게 함(예: 장기요양기관은 `category2 == "계"`만, 병상수는 `item == "총병상수(A)"`만 필터) | `load_korea()` |
| 이상치 | 총인구·65세이상인구 0 이하, 65세이상인구 > 총인구, 고령화율 0~100% 범위 밖, 병상수/요양기관수 음수 등 6개 항목을 코드로 자동 점검(현재 데이터는 전부 통과) | `check_outliers()` |
| 데이터 타입 | 수치형 컬럼은 `pd.to_numeric(..., errors="coerce")`로 float 변환, 연도는 `int`로 통일 | `load_korea()`, `load_japan()` |
| 날짜 형식 | 연(YYYY) 단위로 통일. 한국은 원본 그대로, 일본은 `"YYYY年度"` 문자열에서 연도만 추출 | `load_japan()`의 `year_of()` |
| 범주값 통일 | 일본 도도부현 한자 표기 → 한글 표기 매핑 딕셔너리 구축, 국가코드(KR/JP) 부여 | `JP_PREF_KR`, `df["country"] = ...` |
| 컬럼명 변경 | e-Stat/KOSIS 원본 컬럼명을 `total_pop`/`elderly_pop`/`aging_rate` 등 공통 영문 컬럼명으로 매핑 | `load_korea()`, `load_japan()`의 `rename()` |
| 불필요한 컬럼 | 최종 병합·적재 시 8개 핵심 컬럼만 선택(원본의 주석·범례성 컬럼 제외) | `load_korea()`, `load_japan()`의 반환 컬럼 목록 |
| 파생 컬럼 | 일본 고령화율, 인구 1만명당 병상수, 인구 1만명당 장기요양기관수, 인구증감률(전년 대비) 산출. 한국 고령화율은 KOSIS 원본값 사용 | `add_derived_columns()` |

인구증감률은 pandas에서는 지역별로 연도순 정렬 후 `shift(1)`로, SQL 정제 파이프라인(`sql_cleaning/12`)에서는 전년도 행과의 self-JOIN으로 계산했고 두 결과는 같다. 인프라 격차지수는 전처리 단계가 아니라 분석 단계(`sql/analysis/q5.sql`, Power BI DAX)에서 계산한다.

### 전처리 원칙

```text
원본 데이터
    ↓
데이터 타입 변환 + 필요한 항목만 필터링 (범주값 통일, 중복 방지)
    ↓
컬럼명 매핑 (KOSIS/e-Stat → 공통 스키마)
    ↓
한·일 병합 + 기간 통일 (2015~2023, 결측 사전 차단)
    ↓
이상치 확인
    ↓
파생변수 생성 (밀도 지표, 인구증감률)
    ↓
Dim/Fact 테이블 구성 → SQLite 적재
    ↓
정제 데이터 (인프라 격차지수는 이후 SQL 분석 단계에서 별도 산출)
```

# 2.4 SQL Database 설계

### 데이터베이스명

`aging_infra.db` (SQLite)

### 테이블 구성

지역(region) × 연도(date)를 기준으로 한 스타 스키마다. 국가 정보는 `Dim_Country`로 분리했다. 적재 연도를 2015~2023으로 통일해 팩트 테이블은 64개 지역 × 9개년 = 576행이며, 결측은 `pop_change_rate`의 각 지역 첫 연도(2015)뿐이다.

| 테이블 | 역할 | 주요 컬럼 |
|---|---|---|
| Dim_Country | 차원 | country PK, country_name_kr, data_source, region_count |
| Dim_Region | 차원 | region_id PK, country FK → Dim_Country, region_name_kr, region_name_local |
| Dim_Date | 차원 | date_id PK, year |
| Fact_RegionStats | 사실(물리 테이블) | region_id FK, date_id FK, 인구·인프라 지표 8개 |
| Fact_Population | 사실(뷰) | Fact_RegionStats의 인구 지표만 분리 |
| Fact_Infra | 사실(뷰) | Fact_RegionStats의 인프라 지표만 분리 |

SQL 분석, Python 시각화, Power BI DAX 측정값은 모두 `Fact_RegionStats`와 `Dim_Region`, `Dim_Date`를 기준으로 한다. `Fact_Population`, `Fact_Infra`는 인구 지표와 인프라 지표를 나눠 보기 위해 같은 테이블 위에 만든 뷰라서 데이터 원본은 하나로 유지된다(`sql/ddl/create_tables.sql`).

# 2.5 ERD

```text
┌──────────────────┐
│ Dim_Country      │
│ country PK       │
│ country_name_kr  │

│ region_id PK     │                       │ date_id PK   │
│ country FK       │                       │ year         │
│ region_name_kr   │                       └──────┬───────┘
│ region_name_local│                              │ 1:N
└────────┬─────────┘                              │
         │ 1:N                                    │
┌────────▼────────────────────────────────────────▼───┐
│ Fact_RegionStats                                    │
│ region_id FK, date_id FK                            │
│ total_pop, elderly_pop, aging_rate, pop_change_rate │
│ medical_beds, care_facility_count                   │
│ medical_beds_per_10k, care_facility_per_10k         │
└──────────────────────────┬──────────────────────────┘
                           │ VIEW
            ┌──────────────┴──────────────┐
```

`Fact_RegionStats`는 지역 × 연도 조합마다 한 행이고 576행(64지역 × 9개년)이다. 두 뷰는 `Dim_Date`와 조인해 `year`를 바로 붙여서, 연도 숫자로 바로 필터링할 수 있게 했다.

# 3.4 주요 DAX 측정값

| 측정값 | DAX | 용도 |
|---|---|---|
최종 대시보드에서 쓴 측정값이다(발표자료 30~32장). 순위는 모두 **국가 안에서** 매긴다. 처음에는 `RANKX(ALL(Dim_Region), ...)`로 64개 지역 전체 순위를 매겼는데, 이렇게 하면 격차 상위 지역이 전부 일본으로 쏠려서(Insight 2) 국가별 순위로 바꿨다.

| 측정값 | 용도 |
|---|---|
| `고령화율_2023`, `병상수_1만명당_2023`, `요양기관수_1만명당_2023` | 각 지역의 2023년 기준값 |
| `인프라점수_2023` | 병상수 + 요양기관수 (1만명당) |
| `고령화율_국가내순위_2023`, `인프라_국가내순위_2023` | 같은 나라 안에서의 순위 |
| `인프라_격차지수_2023` | 고령화율 순위 − 인프라 순위 (음수가 클수록 인프라 확충이 시급) |
| `인프라확충시급_순위_2023` | 격차지수를 다시 국가 안에서 순위화 |
| `고령화증가폭_국가내순위` | 2015~2023 고령화율 증가폭의 국가 내 순위 |

```DAX
고령화율_2023 =
CALCULATE(
    MAX(Fact_RegionStats[aging_rate]),
    REMOVEFILTERS(Dim_Date),
    Dim_Date[year] = 2023
)
```

```DAX
고령화율_국가내순위_2023 =
VAR CurrentCountry = SELECTEDVALUE(Dim_Region[country])
RETURN
RANKX(
    FILTER(ALL(Dim_Region), Dim_Region[country] = CurrentCountry),
    [고령화율_2023], , DESC, SKIP
)
```

```DAX
인프라_격차지수_2023 =
[고령화율_국가내순위_2023] - [인프라_국가내순위_2023]
```

병상수(1만명당 약 55~276개)와 요양기관수(1만명당 약 0.4~8.6개)를 그대로 더하기 때문에 인프라 점수가 사실상 병상수로 정해진다는 한계가 있다. 이후 두 지표를 국가별 z-score로 바꿔 같은 비중으로 반영한 보완 버전을 `sql/analysis/q6.sql`에서 계산했다(결과는 README '보완: 인프라 격차지수 표준화' 참고).

### 핵심 Insight

**Insight 1: 한국의 고령화 속도는 일본의 약 1.8배다.** 2015~2023년 평균 고령화율은 한국 13.8%→19.6%(연평균 +0.72%p), 일본 28.3%→31.6%(연평균 +0.41%p)로 변화했다. 일본은 이미 높은 고령화율에서 완만하게 증가하는 반면, 한국은 낮은 출발점에서 약 1.8배 빠른 속도로 쫓아가고 있어 인프라를 준비할 시간이 더 촉박하다. 같은 기간 부산광역시(+8.0%p), 강원특별자치도(+7.1%p), 울산광역시(+7.1%p), 경상북도(+7.0%p), 대구광역시(+6.9%p) 순으로 증가폭이 컸다(`sql/analysis/q1.sql`, `figures/02_aging_rate_trend.png`, `figures/10_aging_increase_top_regions.png`).

**Insight 2: 인프라 격차는 64개 지역 전체가 아니라 국가별 순위로 봐야 한다.** 인프라 격차지수(고령화율 순위 − 인프라밀도 순위)를 64개 지역 전체에서 계산하면 상위 15개가 모두 일본 지역이다. 일본의 고령화율이 전반적으로 한국보다 높아서 생기는 쏠림이라, 각 지역의 인프라 부족을 보여주지는 못한다. 국가별로 따로 순위를 매기면 한국에서는 강원특별자치도(고령화율 24.0%로 한국 내 4위인데 인구 1만명당 병상수는 108.2로 17개 시·도 평균 151.8보다 29% 낮음), 일본에서는 야마가타현이 각각 자국 내 인프라 확충 최우선 지역으로 나온다(`sql/analysis/q5.sql`의 전역 순위와 `figures/08_infra_gap_ranking.png`의 국가별 순위를 비교해서 확인함).

**Insight 3: 지표 정의가 다르면 국가 간 비교에서 상관관계 부호 자체가 뒤집힐 수 있다.** 고령화율과 장기요양(돌봄) 인프라밀도의 상관계수는 한국 내부(+0.742), 일본 내부(+0.819) 모두 뚜렷한 양의 상관인데, 두 나라 데이터를 합쳐서 계산하면 -0.673으로 부호가 반대가 된다. 원인은 통계 정의 범위 차이다. 한국 KOSIS의 "장기요양기관 기관수"는 방문요양·주야간보호·노인요양시설 등 모든 서비스유형을 합친 값이고, 일본 e-Stat의 "介護老人福祉施設数"는 그중 입소시설(특별양호노인홈) 한 유형만 센 값이라 한국 쪽 절대값이 원래 훨씬 크다. 이 정의 차이를 모르고 국가를 합쳐서 보면 "돌봄 인프라가 많을수록 고령화율이 낮다"는 잘못된 결론에 이를 수 있다.
